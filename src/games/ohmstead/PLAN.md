## 1. Agreed

- Genre: factory builder, persistent, not a roguelite.
- Theme: electronics manufacturing, from raw ore to a working computer (career tie: ECE).
- View: isometric 2.5D.
- Progression: tech tree to a final product, then sandbox. Campaign length target 4 to 6 hours, with a defined end like Factorio's rocket and Satisfactory's Project Assembly, and the world continues afterward.
- Main inspiration: Factorio ("the pinnacle of the genre"). Secondary: Satisfactory, Shapez, Dyson Sphere Program.
- Logic Lab: required to finish the campaign, but gentle (3 to 4 simple specs, built-in hints).
- Research model: hybrid. Dock missions are the main objective and grant unlock points for the tech tree. Labs consume belted component parts (Factorio style) to research/investigate components and machines, and some missions are gated until the relevant part is researched. See GDD section 9.
- Hazards: none, peaceful.
- Map: large bounded procedural map from a seed, generated in chunks, expanding in rings. Feels infinite, is not.
- Tech: PixiJS renderer + pure-JS deterministic engine confirmed. Carlos asked that it stay expandable beyond the web (desktop via Tauri/Electron, later Worker/WASM sim); the engine/render split must be kept strict.
- Scope: medium (about 2 to 3 months, content waves plus polish passes).
- Location: `src/games/ohmstead/` in the Portafolio repo, routed at `/games/ohmstead`.
- Tech and exact content details are still to be discussed with Carlos (his words: decide after the concept is nailed down).

## 2. Tech recommendation (Proposed)

Why DOM/React is out: a factory has hundreds of machines and thousands of moving items. Elementa's approach (React tree per element) will not survive that. The renderer must draw to a canvas.

| Option | Verdict |
|---|---|
| React + DOM | No. Too many nodes. Use only for UI panels. |
| Canvas 2D by hand | Works for a small factory, hits a CPU wall as it grows. |
| **PixiJS (WebGL sprite batching)** | **Recommended.** Fast 2D, great for isometric sprites, small API, works in a Vite app, 10k+ moving sprites is fine. |
| Three.js | Overkill for isometric 2.5D unless full 3D is wanted. Reconsider only if Carlos moves to full 3D. |
| Godot / Unity | Better editor tooling but breaks the "play it inside the portfolio" goal and the code-art workflow. Not recommended. |

Architecture:
```
src/games/ohmstead/
  OhmsteadGame.jsx      React shell: menus, HUD, panels, mounts the canvas
  engine/                pure JS, no DOM, deterministic, Node-testable
    sim.js               fixed tick loop, world state
    grid.js              map, placement, collision
    belts.js             belt segments, item positions, splitters
    machines.js          recipe runner, buffers, status reasons
    power.js             network solve, satisfaction %
    research.js          tech tree state
    logic/               Logic Lab gate evaluator and spec tests
    rng.js               seeded RNG (port from elementa)
  render/                PixiJS only: iso projection, sprites, camera, overlays
  data/                  recipes.js, machines.js, research.js, specs.js
  art/                   procedural sprite generators (SVG/canvas, code art)
  GDD.md  PLAN.md  CONTENT.md
```
Key rule: the engine never imports render or React, so everything can be verified with Node scripts like the Elementa reducer, and the sim can run headless for balancing.

Performance targets: 60 fps with 300 machines and 5,000 belt items on a mid laptop. Simulation tick 20 Hz decoupled from render. Belts store item offsets per segment rather than per-item objects in a global list.

## 5. Risks

- Scope creep from Factorio-style depth (trains, circuits, blueprints). Mitigation: GDD section 13 lists them as post-1.0.
- Isometric depth sorting with tall machines. Mitigation: footprints are fixed rectangles, draw order by (x + y) then height.
- Logic Lab balancing and specs. Mitigation: 6 to 10 hand-authored specs, tested in Node.
- Art burden of animated machines. Mitigation: a small shared set of procedural animation primitives (spin, glow, blink, piston).
